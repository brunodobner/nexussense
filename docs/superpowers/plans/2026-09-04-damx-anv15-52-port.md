# Port das personalizações ANV15-52 — Plano de Implementação

> **Para executores agênticos:** SUB-SKILL OBRIGATÓRIA: use
> `superpowers:subagent-driven-development` (recomendado) ou
> `superpowers:executing-plans` para implementar tarefa a tarefa. Os passos
> usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** Tornar `original/` (DAMX 1.0.2) plenamente funcional no Acer
Nitro ANV15-52, com o módulo sobrevivendo a atualizações de kernel via DKMS
e o instalador funcionando em Arch, Debian, Fedora e openSUSE.

**Arquitetura:** `original/` é o alvo; `versaopessoal/` é especificação de
requisitos, nunca fonte de cópia. O `setup.sh` do upstream permanece a base
do instalador (ele já traz multi-distro, tecla Nitro, `tmpfiles.d` e limpeza
de legado) e recebe DKMS enxertado em `install_drivers()`. A decisão de
toolchain (GCC × Clang) desce do instalador para o Makefile, onde passa a
ser tomada **por kernel-alvo** — única forma correta num sistema com kernels
dos dois tipos.

**Stack:** C (módulo de kernel Linux), GNU Make, DKMS, Bash, systemd.

**Spec:** `docs/superpowers/specs/2026-09-04-damx-anv15-52-port-design.md`

## Restrições globais

Valem para todas as tarefas.

- **Só `original/` é modificado.** `versaopessoal/` está congelada como
  referência. Nenhuma tarefa escreve nela.
- **Portar por intenção, não por transcrição.** Copiar texto de
  `versaopessoal/` sem reavaliar é erro de execução, não atalho.
- **Nome do pacote DKMS:** `linuwu_sense`. **Versão:** derivada de
  `DRIVER_VERSION` em `original/Linuwu-Sense/src/linuwu_sense.c` (hoje
  `25.701`) — **nunca** literal em script.
- **Kernels alvo, com toolchain esperado:**
  - `6.18.48-1-cachyos-lts` → Clang
  - `7.2.2-1-cachyos` → Clang
  - `7.2.2-arch1-1` → **GCC** (é o caso que a estratégia do upstream quebra)
- **Modelo alvo:** DMI `Acer` / `Nitro ANV15-52`, classificado como
  `&quirk_acer_nitro`.
- **Um commit por tarefa**, prefixo conforme §5 da spec
  (`build:`, `driver:`, `fix:`, `install:`, `systemd:`, `test:`).
- **Nada de `sudo` dentro de Makefile.**
- **Sem afirmação de sucesso sem saída de comando que a sustente.** Se um
  passo não puder ser verificado, ele é reportado como não verificado.
- **Recuperação sempre disponível:** `git reset --hard upstream/1.0.2 --
  original/` restaura `original/` ao estado do upstream, e
  `sudo modprobe linuwu_sense` recarrega o módulo do DKMS já instalado.

```make
obj-m := src/linuwu_sense.o

MODNAME := linuwu_sense

# Kernel alvo: o DKMS injeta KERNELRELEASE; fora dele, o kernel corrente.
ifeq ($(KERNELRELEASE),)
  KVER ?= $(shell uname -r)
else
  KVER := $(KERNELRELEASE)
endif

KDIR := /lib/modules/$(KVER)/build
MDIR := /lib/modules/$(KVER)/kernel/drivers/platform/x86
PWD  := $(shell pwd)

# ---------------------------------------------------------------------
# Toolchain: decidido pelo kernel ALVO, nunca pelo kernel em execucao.
#
# Um modulo externo precisa do mesmo compilador do kernel para o qual e
# compilado. Forcar LLVM=1 globalmente quebra kernels GCC (ex.: o pacote
# "linux" do Arch) com "unknown argument: -mindirect-branch=thunk-extern";
# nao forcar nada quebra os kernels Clang. Num sistema com os dois tipos
# instalados, so a deteccao por alvo funciona.
#
# O DKMS ja detecta clang sozinho e passa LLVM=1 na linha de comando;
# $(origin LLVM) preserva esse override.
# ---------------------------------------------------------------------
ifeq ($(origin LLVM),undefined)
  ifneq ($(shell grep -sh CONFIG_CC_IS_CLANG=y $(KDIR)/.config /boot/config-$(KVER)),)
    LLVM := 1
  endif
endif

ifeq ($(LLVM),1)
  TOOLCHAIN := LLVM=1 LLVM_IAS=1
  TOOLCHAIN_NAME := LLVM
else
  TOOLCHAIN :=
  TOOLCHAIN_NAME := GCC
endif

.PHONY: all clean install uninstall toolchain-info

all:
	@echo "Building $(MODNAME) for kernel $(KVER) [$(TOOLCHAIN_NAME)]..."
	$(MAKE) -C $(KDIR) M=$(PWD) $(TOOLCHAIN) modules

# Diagnostico: usado pelo test-toolchain.sh e util em suporte.
toolchain-info:
	@echo "KVER=$(KVER) TOOLCHAIN=$(TOOLCHAIN_NAME) KDIR=$(KDIR)"

clean:
	-$(MAKE) -C $(KDIR) M=$(PWD) clean
	@rm -f src/*.o src/*.mod src/*.mod.c src/.*.cmd
	@rm -f *.mod.c *.symvers *.order Module.markers modules.order Module.symvers

# Caminho manual, para quando nao ha DKMS. O setup.sh cuida de servicos,
# grupos e tmpfiles; este alvo so instala o modulo. Requer root -- sem
# sudo embutido, que quebraria build nao-interativo.
install: all
	install -d $(MDIR)
	install -m 644 src/$(MODNAME).ko $(MDIR)
	depmod -a $(KVER)
	@echo "$(MODNAME) instalado em $(MDIR)"

uninstall:
	rm -f $(MDIR)/$(MODNAME).ko
	depmod -a $(KVER)
	@echo "$(MODNAME) removido de $(MDIR)"
```

```bash
#!/bin/bash
# Verifica que o dkms.conf registra e COMPILA nos dois tipos de toolchain.
# Usa uma versao de teste para nao colidir com a instalacao real.
set -u
SRC="$(cd "$(dirname "$0")" && pwd)"
VER_TESTE="0.0.0-test"
DEST="/usr/src/linuwu_sense-${VER_TESTE}"
fail=0

if [ "$EUID" -ne 0 ]; then echo "Rode como root: sudo $0"; exit 2; fi

limpar() {
  dkms remove -m linuwu_sense -v "$VER_TESTE" --all >/dev/null 2>&1 || true
  rm -rf "$DEST" "/var/lib/dkms/linuwu_sense/${VER_TESTE}"
}
trap limpar EXIT
limpar

mkdir -p "$DEST"
cp -r "$SRC/src" "$SRC/Makefile" "$DEST/"
sed "s/^PACKAGE_VERSION=.*/PACKAGE_VERSION=\"${VER_TESTE}\"/" \
    "$SRC/dkms.conf" > "$DEST/dkms.conf"

if dkms add -m linuwu_sense -v "$VER_TESTE" >/dev/null 2>&1; then
  echo "  OK   dkms add"
else
  echo "  FALHA dkms add"; exit 1
fi

for k in 7.2.2-arch1-1 7.2.2-1-cachyos; do
  if dkms build -m linuwu_sense -v "$VER_TESTE" -k "$k" >/dev/null 2>&1; then
    printf '  OK   dkms build %s\n' "$k"
  else
    printf '  FALHA dkms build %s\n' "$k"
    fail=1
  fi
done

exit $fail
```

# Install build dependencies based on distribution.
# Kernel headers are required for any module build; DKMS is required for
# the module to survive kernel upgrades. Neither base-devel nor
# build-essential includes headers, so they are requested explicitly.
install_build_deps() {
  if command -v pacman &> /dev/null; then
    # Arch-based (including CachyOS, Manjaro, EndeavourOS).
    # linux-headers covers the stock kernel; other kernels (linux-lts,
    # linux-cachyos, ...) need their own -headers package, which
    # check_kernel_headers reports on.
    pacman -S --needed --noconfirm base-devel linux-headers dkms
    if is_llvm_kernel; then
      pacman -S --needed --noconfirm clang llvm lld
    fi
  elif command -v apt-get &> /dev/null; then
    apt-get update
    apt-get install -y build-essential dkms "linux-headers-$(uname -r)"
  elif command -v dnf &> /dev/null; then
    dnf install -y gcc make kernel-devel dkms
  elif command -v zypper &> /dev/null; then
    zypper install -y gcc make kernel-devel dkms
  else
    echo -e "${YELLOW}Unknown package manager. Install build tools, kernel headers and dkms manually.${NC}"
    return 1
  fi
}

# Report which installed kernels have usable headers.
# DKMS builds for every kernel it finds, so a kernel without headers is a
# build failure waiting to happen -- worth naming up front rather than
# hitting mid-install.
check_kernel_headers() {
  local kver missing=0
  echo -e "${BLUE}Checking kernel headers...${NC}"
  for kver in $(ls /lib/modules); do
    if [ -d "/lib/modules/${kver}/build" ]; then
      echo -e "  ${GREEN}OK${NC}      ${kver}"
    else
      echo -e "  ${YELLOW}MISSING${NC} ${kver}"
      missing=$((missing + 1))
    fi
  done

  if [ "$missing" -gt 0 ]; then
    echo -e "${YELLOW}${missing} kernel(s) without headers. DKMS will skip them.${NC}"
    echo -e "${YELLOW}Install the matching headers package (e.g. linux-lts-headers) to cover them.${NC}"
  fi

  # Only the running kernel is fatal -- it is the one we must load into now.
  if [ ! -d "/lib/modules/$(uname -r)/build" ]; then
    echo -e "${RED}Error: no headers for the running kernel ($(uname -r)).${NC}"
    return 1
  fi
  return 0
}

# Read the driver version from the source of truth.
# Hardcoding it means a future upstream bump silently makes the installer
# operate on the wrong DKMS package.
driver_version() {
  grep -oP '#define DRIVER_VERSION "\K[^"]+' Linuwu-Sense/src/linuwu_sense.c
}

install_drivers() {
  echo -e "${YELLOW}Installing Linuwu-Sense drivers...${NC}"

  if [ ! -d "Linuwu-Sense" ]; then
    echo -e "${RED}Error: Linuwu-Sense directory not found!${NC}"
    echo "Run this script from the directory containing the Linuwu-Sense folder."
    pause
    return 1
  fi

  if ! command -v make &> /dev/null || ! command -v dkms &> /dev/null; then
    echo -e "${YELLOW}Installing build tools...${NC}"
    install_build_deps || { pause; return 1; }
  fi

  check_kernel_headers || { pause; return 1; }

  local ver
  ver=$(driver_version)
  if [ -z "$ver" ]; then
    echo -e "${RED}Error: could not read DRIVER_VERSION from the source.${NC}"
    pause
    return 1
  fi
  echo -e "${BLUE}Driver version (from source): ${ver}${NC}"

  if ! command -v dkms &> /dev/null; then
    echo -e "${YELLOW}DKMS unavailable; falling back to a single-kernel build.${NC}"
    echo -e "${YELLOW}The module will NOT survive kernel upgrades.${NC}"
    ( cd Linuwu-Sense && make clean && make && make install ) || {
      echo -e "${RED}Error: Failed to build Linuwu-Sense drivers${NC}"
      pause
      return 1
    }
    configure_acer_wmi_conflict
    return 0
  fi

  # Remove any previous registration. DKMS state lives in /var/lib/dkms,
  # not /usr/src -- deleting only /usr/src leaves an orphan record and the
  # next 'dkms add' fails.
  echo -e "${BLUE}Clearing previous DKMS registration...${NC}"
  dkms remove -m linuwu_sense -v "$ver" --all &> /dev/null || true
  rm -rf "/usr/src/linuwu_sense-${ver}"
  rm -rf "/var/lib/dkms/linuwu_sense/${ver}"

  echo -e "${BLUE}Staging source in /usr/src/linuwu_sense-${ver}...${NC}"
  mkdir -p "/usr/src/linuwu_sense-${ver}"
  cp -r Linuwu-Sense/src Linuwu-Sense/Makefile "/usr/src/linuwu_sense-${ver}/"
  sed "s/^PACKAGE_VERSION=.*/PACKAGE_VERSION=\"${ver}\"/" \
      Linuwu-Sense/dkms.conf > "/usr/src/linuwu_sense-${ver}/dkms.conf"

  if ! dkms add -m linuwu_sense -v "$ver"; then
    echo -e "${RED}Error: dkms add failed${NC}"
    pause
    return 1
  fi

  # Build for every kernel that has headers, not just the running one --
  # that is the whole point of DKMS.
  local kver built=0
  for kver in $(ls /lib/modules); do
    [ -d "/lib/modules/${kver}/build" ] || continue
    echo -e "${BLUE}Building for ${kver}...${NC}"
    if dkms install -m linuwu_sense -v "$ver" -k "$kver" &> /dev/null; then
      echo -e "  ${GREEN}OK${NC} ${kver}"
      built=$((built + 1))
    else
      echo -e "  ${YELLOW}FAILED${NC} ${kver} (continuing)"
    fi
  done

  if [ "$built" -eq 0 ]; then
    echo -e "${RED}Error: the module built for no kernel at all.${NC}"
    echo -e "${YELLOW}Diagnostics: dkms install -m linuwu_sense -v ${ver} -k $(uname -r)${NC}"
    pause
    return 1
  fi

  # 'dkms status' exits 0 even for a package that does not exist, so the
  # test must look for the word, not the exit code.
  if ! dkms status "linuwu_sense/${ver}" | grep -q installed; then
    echo -e "${RED}Error: DKMS reports no installed module for linuwu_sense/${ver}${NC}"
    pause
    return 1
  fi

  configure_acer_wmi_conflict

  echo -e "${GREEN}Linuwu-Sense installed via DKMS for ${built} kernel(s).${NC}"
  return 0
}

# acer_wmi claims the same WMI GUIDs as linuwu_sense. Without the
# blacklist it wins the race at boot and linuwu_sense loads but never
# binds, leaving sysfs empty.
configure_acer_wmi_conflict() {
  echo -e "${YELLOW}Resolving acer_wmi conflict...${NC}"

  cat > /etc/modprobe.d/blacklist-acer_wmi.conf << 'EOL'
# Installed by DAMX setup.sh
# acer_wmi claims the same WMI GUIDs as linuwu_sense.
blacklist acer_wmi
EOL

  # The blacklist only takes effect at next boot; unload now as well.
  if lsmod | grep -q '^acer_wmi'; then
    modprobe -r acer_wmi 2>/dev/null \
      || echo -e "${YELLOW}Could not unload acer_wmi; reboot to complete.${NC}"
  fi

  echo "linuwu_sense" > /etc/modules-load.d/linuwu_sense.conf
  depmod -a

  modprobe linuwu_sense 2>/dev/null \
    || echo -e "${YELLOW}Could not load linuwu_sense; reboot to complete.${NC}"

  if [ -d /sys/devices/platform/acer-wmi/nitro_sense ] \
     || [ -d /sys/devices/platform/acer-wmi/predator_sense ]; then
    echo -e "${GREEN}Driver bound; sysfs populated.${NC}"
  else
    echo -e "${YELLOW}sysfs not populated yet; reboot to complete.${NC}"
  fi
}
